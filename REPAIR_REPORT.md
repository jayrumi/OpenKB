# OpenKB Flash: исправления и реальная повторная проверка

## Итог

Исправления выполнены в development-ветке `fix/codex-stream-compilation-recovery` поверх `47ea153`. **Production не развёрнут и не изменён.**

Реальная проверка на незарегистрированной копии КБ прошла: адресная перекомпиляция → query/SSE → chat в одном процессе и одном lifespan API. Уже построенный Flash-индекс использован без повторного индексирования. Дополнительно проверен настоящий существующий Web UI в браузере: вопрос, tool calls, потоковый ответ и правильная ссылка на страницу PDF; JavaScript-ошибок нет.

## Исправлено

1. **Codex SSE HTTP 400 `Stream must be set to true`.** LiteLLM 1.87.2 выбирал fake streaming по устаревшим метаданным модели и удалял обязательный `stream=true` из запроса. Узкий in-process shim включает native SSE только для ChatGPT-конфигурации этой версии. Имена моделей, другие провайдеры и файлы установленных зависимостей не меняются.
2. **Ложный успех неполной компиляции.** Ошибки обязательных concept/entity tasks теперь агрегируются до публикации страниц, backlinks и успешного индекса. Add не регистрирует такой документ как успешно добавленный. Ошибка сообщает имя страницы и тип исключения, не тело ответа провайдера.
3. **Безопасная перекомпиляция.** CLI и REST используют общую транзакцию с откатом summary/index/shared concept/entity pages. Raw PDF, база PageIndex и завершённый кеш индексирования не входят в эту транзакцию. Отмена распространяется; грязный rollback останавливает пакет.
4. **Закрытый HTTP-клиент после компиляции.** Документ больше не вызывает глобальное закрытие кешированных клиентов LiteLLM. Очистка перенесена на завершение владеющего event loop: finite CLI/thread jobs и lifespan API. Удаляются и закрываются только записи текущего loop, чужие клиенты не затрагиваются. Исправлено и освобождение coroutine при отказе запуска loop.

## Расход и границы утверждений

За все этапы этого repair-тестирования, включая первоначальную неудачу lifecycle и повторные проверки: **34 application LLM calls / 34 зарегистрированные HTTP attempts**. Подтверждённый usage: **38 836 токенов**. У **24 вызовов** тестовый счётчик не получил usage, преимущественно для streaming; поэтому полный фактический/биллинговый расход неизвестен. Эти вызовы не считаются бесплатными. Токены агентской разработки в эти цифры не входят. После восстановления с места падения новых реальных LLM-запросов не выполнялось: использованы сохранённые результаты и offline-тесты.

Это проверка на небольшом доверенном четырёхстраничном PDF. Большая книга Кимбалла и нагрузочный/масштабный benchmark не запускались. Новое индексирование после исправлений намеренно не повторялось: Flash-этап был реально проверен ранее, а восстановление обязано переиспользовать его результат.

Остаются риски из основного отчёта: PyPDF2 3.0.1 CVE-2023-36464, отсутствие mid-tree resume, непроверенная передача async-to-thread cancellation к worker, риск конкурентного OAuth refresh, отсутствие гарантированного output-token cap у ChatGPT transport. Дополнительный новый серверный/сетевой доступ не включался. Credentials не переносились и не публиковались.
